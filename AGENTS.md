# AI assistant guidance

## Help a student complete the computer setup

Apply this section when a student asks for help installing, checking, updating, or troubleshooting the course environment. It covers setup support only.

- Read [README.md](README.md) first and follow its computer setup instructions. Use [dependency compatibility notes](docs/setup-dependencies.md) and [additional software requirements](docs/additional-software.md) when diagnosing a problem. The README's linked official documentation is the starting point for checking installation instructions. Reuse the screenshots in [assets/setup/](assets/setup/README.md) to explain where to click.
- Assume the student has little or no terminal experience. Explain unfamiliar terms briefly, use the student's operating system's menu names and keyboard shortcuts, and give one manageable step at a time. For each step, say where to act, provide a copyable command or precise clicks, and describe the expected result. When the student is performing the steps, wait for their result before moving on. Do not give the entire setup as one long response.
- Establish the student's operating system and version, processor type, what they have already installed, and where they are stuck. Ask only for information that is missing; use available tool results or screenshots rather than asking the student to repeat it. Distinguish the student's computer from any remote or sandbox environment available to the assistant. A successful check on a remote machine does not verify the student's setup.
- Guide the student through the README sequence: install and check uv and Git; install VS Code and its extensions; clone the public course repository using its HTTPS URL; open the project root; install Python and the locked packages; select the interpreter and notebook kernel; run the readiness checks. Skip steps whose success is already established. Quarto's VS Code extension is included for displaying callout boxes; the separate Quarto application is only needed to render documents.
- Use Python **3.13** and the project's **`.venv`**. Verify the project root contains `pyproject.toml` and `uv.lock` before running project commands. Use `uv python install 3.13` and `uv sync --locked` for the basic environment. Students do not need another environment manager or manual environment activation. Keep existing unrelated Python installations in place.
- The basic setup is for Block 1. **The neural extra is required before Block 2 and from then onwards:** use `uv sync --locked --extra neural` and the README's neural import check. Retain `--extra neural` on subsequent neural sync and run commands; syncing without it removes neural-only packages. Explain that installation success does not guarantee GPU support. If their hardware has a documented limitation, explain it before they try the locked installation and help them report any failure to the instructor.
- Verify that VS Code's interpreter and each notebook's kernel point to the student's course `.venv`, rather than another Python installation. Follow the README's readiness checks and compare the reported executable path with the selected environment. Restart notebook kernels after package changes. Report only checks that actually ran or results the student supplied; do not claim every exercise or GPU workload has been tested.
- For course updates, use `git pull --ff-only` in the cloned project, then the appropriate locked sync command. Preserve completed exercises and local changes. If Git reports an overwrite or divergent history, help the student understand the message and contact the instructor; do not discard changes, force a pull, or reset their repository to bypass it.
- Troubleshoot the actual error before suggesting changes. First check the current folder, command, Python version, environment selection, and whether a newly installed tool needs the terminal or VS Code reopened. Do not edit `pyproject.toml`, regenerate or modify `uv.lock`, change package versions, or replace locked installation with ad hoc package installation to make setup succeed. Do not recommend compilers, CUDA, or permanent PowerShell policy changes as a general setup fix. Consult the additional-software notes for specific runtime errors.
- If installation or the neural check fails, help the student prepare an email to **hauke.licht@uibk.ac.at**, before Block 2 for neural issues. Include OS and version, processor type, the exact command, the complete relevant error, and checks already attempted. Let the student review and send it unless they explicitly ask you to send it. Request only relevant diagnostic output; do not read `.env` files or request passwords, API keys, or other credentials. Remind students to remove secrets from anything they share.
- When the requested setup is complete, give a short checklist of what was verified and any unresolved limitations or next steps. Keep the distinction between the basic setup and readiness for Block 2 clear.
